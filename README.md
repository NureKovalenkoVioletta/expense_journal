# expense_journal

Консольна програма «Журнал особистих витрат» (варіант 3) з дисципліни «Програмування мовою Dart». Лабораторна робота 1 «Функції та обробка колекцій».

Програма розбирає константний набір рядків про витрати, відсіює пошкоджені й недопустимі записи, агрегує коректні та виводить результати в консоль.

## Запуск

```
dart run
dart analyze
```

Потрібен Dart SDK 3.13.4 або новіший.

## Структура програми

| Файл | Призначення |
|---|---|
| `bin/expense_journal.dart` | Точка входу: викликає функції бібліотеки й виводить результати за розділами |
| `lib/expense_data.dart` | Вхідні дані — константа `rawExpenses` (18 рядків, із них 3 пошкоджені та 2 з недопустимими значеннями) |
| `lib/expense_journal.dart` | Уся логіка: розбір, валідація, конвеєри, групування, сортування, звіт, замикання, регулярний вираз, обчислення віку запису |

Логіку винесено в `lib/`, а в `bin/` залишено лише виведення. Так функції не залежать від консолі, і їх можна імпортувати в модульні тести (обов’язкові з ЛР3). Дані відокремлено від логіки в окремий файл, щоб їх можна було змінювати, не торкаючись коду обробки. Каталогу `test/` немає: шаблонний тест перевіряв видалену функцію `calculate()`, а тести вимагаються з ЛР3.

## Вибір типів даних

- **Запис (record) `Expense` з псевдонімом `typedef`.** Класи в ЛР1 не використовуються. Запис дає іменовані поля, незмінність і порівняння за значенням, а `typedef` прибирає повторення довгого типу в сигнатурах.
- **`Expense? parseLine(...)`.** Для пошкодженого рядка функція повертає `null`: очікувана помилка розбору обробляється без винятків і try/catch.
- **`double` для суми.** Для навчального прикладу точності достатньо, суми виводяться з округленням до двох знаків. Для реальних фінансових розрахунків доцільніше зберігати суму в копійках (`int`).
- **`DateTime` для дати.** Розбирається через `DateTime.tryParse`. Метод нормалізує неіснуючі дати (`2026-13-40` → `2027-02-09`), тому некоректна дата у вхідних даних задана неправильним форматом.
- **`String` для валюти й способу оплати.** Допустимі значення перевіряє валідатор: валюту - за множиною, спосіб оплати - регулярним виразом.
- **`Set<String>` для підтримуваних валют.** Значення унікальні, перевірка `contains` проста.
- **`Map<String, List<Expense>>` для груп** — за вимогою методички. `Map<String, double>` — для сум за групами.
- **Запис `({double min, double max, double average})`** як результат статистики: три значення повертаються разом без окремого класу.
- **`final DateTime referenceDate = DateTime(2026, 11, 1)`.** Фіксована дата замість `DateTime.now()`, щоб вивід не залежав від дня запуску. `final`, а не `const`, бо конструктор `DateTime` не є константним.
- **Курси перерахунку в гривні** — константи `uahPerUsd = 45.05` і `uahPerEur = 49.53` (курси на 20.11.2026). Фіксовані значення роблять результат відтворюваним.

## Залежності

Залежностей часу виконання немає.

| Залежність | Тип | Навіщо | Розглянуті альтернативи |
|---|---|---|---|
| `lints` ^6.0.0 | dev | Набір правил `package:lints/recommended.yaml` для `dart analyze` (вимога методички) | `core.yaml` — слабший за вимогу; `flutter_lints` — призначений для Flutter-проєктів |
| `test` ^1.25.6 | dev | Модульні тести, обов’язкові з ЛР3; додано шаблоном `dart create` | Альтернатив у стандартній екосистемі Dart немає |

Залежність `path`, яку додав шаблон, видалено (`dart pub remove path`): вона не використовується. Пакет `collection` не підключено: групування виконано через `fold` із `putIfAbsent`, пошук — через `firstOrNull` з `dart:core`.

## Оператор `!`, `late`, `dynamic`

У коді не використовуються. Місця, де вони могли б з’явитися, розв’язано інакше:

- перерахунок у гривні виконано виразом `switch` за кодом валюти, а не пошуком у `Map`, який повертає nullable-значення й вимагав би `!`;
- в обробнику `replaceAllMapped` тип `Match` звужується до `RegExpMatch` перевіркою `is`, без приведення `as`;
- результати `tryParse` перевіряються на `null`, після чого тип звужується автоматично.
